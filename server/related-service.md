# 其他配套服务

## 个人中心与直播页

`yubo.run` 提供个人中心及直播展示页面。个人中心是客户端登录依赖；直播页是独立的统计消费者，页面加载成功不代表数据录入客户端已经登录或具有权限。

主要资源如下：

| 路径或入口 | 用途 |
| --- | --- |
| `/user/` | QQ／邮箱登录、用户信息及活动管理 |
| `/zc/zc-flight-live.html` | OBS 等浏览器环境使用的直播统计页 |
| `/zc/css/zc-flight-live/` | 共享主题 CSS |
| `/assets/arknights/operator-avatars/operator-avatars.json` | 直播页干员头像清单 |
| `/api/gachalog-zc/get` | 直播页公开统计数据 |
| `/api/gachalog-zc/get-page-style-list` | 直播页与客户端可用主题目录 |

直播页 URL 使用 `live_id` 选择配置，活动、卡池和跟随操作员由服务端决定。页面按服务端的活跃状态与间隔轮询；不活跃时仍以较长间隔检查状态。客户端 ON AIR 控制所选配置的刷新状态，不代表 OBS 推流状态或账户在线状态。

客户端远程加载同一主题目录的 CSS，加载失败时使用本地 `classic.css`。新增共享主题应使服务端主题目录与实际静态资源保持一致；不能只添加一个主题名称而遗漏文件。主题加载失败与业务接口失败应分开排查。

直播页还调用 kusabot 的 `/api/zc/online`，用于特定条件下的开播群通知。这是页面侧的附属能力，不是客户端认证或抽卡写入依赖；联调时应注意其可能产生真实群消息，本说明不提供触发参数或访问值。

## 模型资源生产与分发

本机 ONNX 推理需要 `image_type.onnx`、`gacha10.onnx` 和配套的 `operators.txt`。训练项目负责生成与验证，gachabot 发布模型清单并提供受保护下载，客户端负责校验后安装。

模型更新失败时，客户端现有逻辑允许继续使用已有可用资源；首次安装缺少必需文件时不能据此完成识别。此降级只针对模型资源，不意味着最低版本策略或认证失败也可以离线放行。

模型版本与客户端版本分别管理。模型清单中的最低客户端版本用于兼容性检查，不替代本仓库的客户端最低支持版本策略。

## GitHub 更新服务

客户端固定读取官方 `325-Gaming/zc-flight-statistics` 仓库的 `master` 分支与稳定 Release。

| 资源 | 职责 | 不可用时的行为 |
| --- | --- | --- |
| 根目录 `update-policy.json` | 启动时强制在线验证最低支持版本与提示文案 | 门禁阻止进入业务界面，只能重试或退出 |
| `client/data-entry/version.py` | 已达门槛客户端的可选新版本提示 | 请求失败不阻止已达标且无需恢复更新的客户端启动 |
| GitHub Releases API | 查询稳定版与更新资产 | 强制更新／恢复更新时失败会阻止进入；可选更新检查失败不等于策略失败 |
| Release ZIP 与校验信息 | 下载、校验和安装客户端 | 下载或校验失败不能视作更新成功 |

`version.py` 只静态解析版本号，不执行远端内容。低于门槛或有待恢复更新事务时，不能通过版本提示文件跳过稳定 Release 校验。更新下载和安装仍需要用户确认。

客户端发布由 `.github/workflows/data-entry-release.yml` 维护，使用 `data-entry/vX.Y.Z` 标签，要求包内版本一致。最低版本策略不作为客户端包内的可信替代来源。先发布并验证可用的稳定更新包，再提高策略门槛，避免所有旧客户端被阻挡却没有可用更新目标。

## 系统安装依赖

Windows 安装还依赖 Python 运行时下载、Python 软件包源、Microsoft Visual C++ 运行库与 WebView2。它们属于安装基础设施，不能与 gachabot 的业务 API 可用性混为一谈。排查安装故障时以客户端安装说明和安装日志为准，无需先连接业务数据库或提交测试抽卡。
